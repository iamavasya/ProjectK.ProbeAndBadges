# Сервіс каталогу: вмілості, проби, відзначення

Один каталог для всіх уладів і країв: вмілості, проби, відзначення УПЮ, а згодом КВ, ЗБ, ЛШ, ШБ
та інші відзнаки разом з їхніми зображеннями. Лілейка (прод і селф-хост) лише читає його по API.
Редактори країв правлять його через адмінку. Зовнішні люди надсилають zip, який редактор погоджує.

## Як це влаштовано

```
                 читання (публічне, кешоване)                    запис (через Cloudflare Access)
Лілейка ───► GET /v1/catalog?krai=cz ─┐                ┌── адмінка /admin ◄── редактор краю
сайт,  ───► GET /v1/badges/…         ├─► Worker ──────┤                    ◄── дописувач (zip)
інші        GET /v1/images/… ────────┘    │   │        └── /v1/admin/*, /v1/submissions
                                          │   │
                                   D1 (SQLite)  R2
                                   записи JSON  зображення
                                   ролі, журнал
```

* **Cloudflare Worker** (`worker/`, TypeScript, Hono). Холодного старту немає.
* **D1** зберігає кожен запис каталогу як окремий JSON-документ (`entries`). Там же лежать
  індекс зображень, редактори, подання, журнал змін і лічильник ревізії.
* **R2** зберігає зображення: `images/<name>` для опублікованих і `pending/<id>/<name>` для тих,
  що чекають погодження.
* **Cloudflare Access** відповідає за вхід редакторів (код на пошту або Google). Worker сам
  перевіряє підпис JWT від Access, а роль бере з таблиці `editors` за email.
* **Адмінка** складається з трьох статичних файлів у `worker/public/admin`, і її віддає той самий
  Worker. Окремого деплою немає.

### Чому так, а не інакше

| Варіант | Чому ні |
|---|---|
| Окремий .NET-сервіс в Azure | Ще один деплой, власна авторизація, 0–13 $/міс. |
| Статичний каталог у git + CDN | 0 $, але людям без GitHub правити незручно. |
| Headless CMS (Directus, Strapi) | Потрібен сервер, а доповнення країв лягають незграбно. |
| Модуль усередині Лілейки | Кожен селф-хост мав би свою копію, і каталоги розійдуться. |

## Формат v2

Опис полів і приклади для країв дивіться в [catalog-format.md](catalog-format.md). Еталон —
`catalog/catalog.json`, сконвертований зі старого `badges.json` парсера.

Головне:

* **Ідентифікатори вмілостей і точок проби не змінюються ніколи.** Лілейка зберігає поступ саме
  за ними, і тести в обох валідаторах це перевіряють.
* **Доповнення краю** (`overrides`) змінює чужий запис лише для свого краю: додає або прибирає
  пункти вимог чи точки проби, міняє назву або ховає запис. Нові пункти мають id з префіксом
  краю (`cz-1`), тож ніколи не зіткнуться з базовими.
* **Відзначення й відзнаки** — це одна сутність `awards` з полем `group`
  (`upyu-vidznachennia`, `kv`, `zb`, `lsh`, `shb`). Нова група не потребує змін схеми.
* Записи не видаляються, а **виводяться з ужитку** (`status: retired`). API їх більше не віддає,
  але поступ людей на них лишається валідним.

## API

### Публічне, без входу

| Запит | Що віддає |
|---|---|
| `GET /v1/catalog?krai=cz` | весь каталог так, як його бачить край: доповнення застосовані, виведені записи прибрані, зображення мають URL, нотатки редакторів прибрані |
| `GET /v1/badges?krai=&ulad=&category=&origin=&status=&family=&q=` | вмілості з фільтрами (`origin` — край, що затвердив) |
| `GET /v1/badges/{id}?krai=` | одна вмілість |
| `GET /v1/probes?krai=&ulad=`, `GET /v1/probes/{id}?krai=` | проби з розділами й точками |
| `GET /v1/awards?krai=&group=&ulad=`, `GET /v1/awards/{id}` | відзначення й відзнаки |
| `GET /v1/categories` | спеціалізації |
| `GET /v1/images/{name}?v={sha}` | зображення; з `v` кешується назавжди |

Кешування влаштоване так. Кожен запис збільшує ревізію. Зібраний каталог для краю лежить у
Cache API під ключем з ревізією, тому типовий запит коштує одне читання D1. Відповіді мають
`ETag` і `Cache-Control: public, max-age=60, stale-while-revalidate=600`, тож зміни видно
протягом хвилини. Зображення мають у URL хеш вмісту і кешуються назавжди. SVG віддається з CSP
`default-src 'none'`.

### Для редакторів (за Access)

| Запит | Хто | Що робить |
|---|---|---|
| `GET /v1/admin/me` | усі | хто я і що можу |
| `GET /v1/admin/catalog` | усі | збережений каталог, з доповненнями й виведеними записами |
| `PUT /v1/admin/entries/{badges\|probes\|awards\|categories\|overrides}/{id}` | редактор свого краю, власник | створити або змінити запис |
| `DELETE /v1/admin/entries/…/{id}` | те саме | вивести з ужитку; категорії й доповнення видаляються |
| `PUT /v1/admin/images/{name}` | редактор, власник | завантажити зображення; замінити наявне може лише власник |
| `POST /v1/submissions` | усі | надіслати `catalog.json` на погодження; відповідь містить звіт перевірки й список зображень, яких бракує |
| `PUT /v1/submissions/{id}/images/{name}` | автор подання | докласти зображення до подання |
| `GET /v1/admin/submissions`, `POST …/{id}/approve`, `POST …/{id}/reject` | редактор краю подання, власник | погодити або відхилити |
| `GET/PUT/DELETE /v1/admin/editors/{email}` | власник | ролі |
| `GET /v1/admin/audit`, `GET /v1/admin/export` | редактор, власник | журнал змін і повна вивантажка |

### Ролі

* **Власник** (`OWNER_EMAILS` або роль `owner`) може все.
* **Редактор краю** змінює записи й доповнення свого краю, додає нові категорії та погоджує
  подання, якщо всі зміни в них стосуються його краю.
* **Дописувач** лише надсилає подання. Застосовує їх редактор або власник.

## Як зовнішні люди додають вмілості

1. Людина отримує роль дописувача або редактора краю і входить в `/admin` через код на пошту.
2. Вона пакує `catalog.json` (шаблон у [catalog-format.md](catalog-format.md)) і теку `images/`
   у zip.
3. В адмінці натискає «Завантажити zip». Архів розпаковується в браузері, бо Worker на
   безкоштовному тарифі має 10 мс CPU на запит. `catalog.json` іде на перевірку, і людина одразу
   бачить звіт: помилки, попередження, що буде додано чи змінено, яких зображень бракує. Потім
   зображення вантажаться по одному, кожне перевіряється (розмір ≤ 2 МБ, тип за сигнатурою,
   SVG без скриптів).
4. Редактор застосовує подання одразу. Подання дописувача чекає у вкладці «Подання», поки його
   не погодить редактор краю або власник.

Перевірити zip офлайн, до надсилання: `dotnet run --project tools/ProjectK.Catalog.Cli -- validate prague.zip --against catalog`.

## Вартість

| Що | Безкоштовний ліміт | Наше навантаження |
|---|---|---|
| Workers | 100 тис. запитів на день, 10 мс CPU на запит | кілька тисяч запитів на день, переважно з кешу |
| D1 | 5 ГБ, 5 млн читань рядків і 100 тис. записів на день | ~1 МБ, одне читання на некешований запит |
| R2 | 10 ГБ, вихідний трафік безкоштовний | ~6 МБ зображень |
| Access | до 50 користувачів | кілька редакторів |

**Разом 0 $ на місяць.** Є одне вузьке місце: CPU. Збирання повного каталогу для краю, коли
кешу ще немає, займає близько 10 мс, тобто рівно на межі безкоштовного ліміту. Це трапляється раз
на ревізію і край у кожному дата-центрі, а не на кожен запит. Якщо в логах з'являться помилки
1102 (перевищено CPU), Workers Paid за 5 $/міс дає 30 с CPU і знімає питання. Першу заливку
каталогу через API не робимо, вона йде скриптом (див. нижче).

## Розгортання (один раз)

```bash
cd worker
npm install
npx wrangler login
npx wrangler d1 create catalog           # id вписати в wrangler.jsonc
npx wrangler r2 bucket create projectk-catalog
npm run db:migrate:remote
node scripts/seed.mjs --remote           # каталог і зображення з ../catalog
npm run deploy
```

Далі в Cloudflare Zero Trust потрібно створити Access application (self-hosted) на домен
каталогу. Її шляхи: `/admin`, `/v1/admin`, `/v1/submissions`. Політика: одноразовий код на пошту
для всіх (роль однаково перевіряє Worker) або лише для переліку адрес. Team domain і AUD tag
вписати в `wrangler.jsonc` (`ACCESS_TEAM_DOMAIN`, `ACCESS_AUD`), а Worker прив'язати до
власного домену (наприклад, піддомену `catalog.` основного домену Лілейки), бо Cache API працює лише на власному домені.

Локально:

```bash
cd worker
printf 'ENVIRONMENT=dev\nDEV_ACCESS_EMAIL=you@example.com\n' > .dev.vars
npm run db:migrate:local && node scripts/seed.mjs --local
npm run dev                               # http://localhost:8787/admin/
npm test                                  # Vitest на справжніх D1/R2 у Miniflare
```

## Перехід Лілейки (наступний PR)

1. **Бібліотека `ProjectK.ProbeAndBadges`** отримує джерело `CatalogApi` (`CatalogApiUrl`,
   `Krai`). Воно читає `/v1/catalog?krai=` з ETag, тримає останній знімок на диску для старту
   без мережі і мапить v2 у теперішні `Badge` і `Probe`. Пункти вимог склеюються в markdown,
   `ImagePath` стає повним URL. Наявні джерела (реліз парсера, вбудований seed) лишаються як
   запасні.
2. **Лілейка** змінює лише пакет і `ProbeAndBadges:DataSource` у конфігу. Поступ не мігрує, бо
   id ті самі.
3. **Фронтенд** бере зображення за публічним URL каталогу напряму. `/badges_images` і
   `/api/awards/images/{level}` з авторизацією більше не потрібні, тож зникає розпаковування
   zip на старті API, а 49 МБ картинок з образу.
4. Далі: краєві вимоги в картці людини (`krai` з профілю краю), відзнаки КВ, ЗБ, ЛШ, ШБ у
   життєписі.

## Що лишилось відкритим

* Домен каталогу і хто ще, крім Rost, буде власником.
* Чи потрібен окремий каталог для селф-хоста, який не має доступу до інтернету. Зараз селф-хост
  читає публічний каталог, а свої зміни край вносить у спільний через редактора.
* Мова інтерфейсу адмінки та перекладу полів (`title` поки лише українською; переклади можна
  додати новим полем без зміни ідентифікаторів).
