API

Усі запити нижче публічні: ключ не потрібен, CORS відкритий. Відповіді в JSON. API віддає лише те, що вже опубліковано. Виведені з ужитку записи й нотатки редакторів не потрапляють у відповідь.

ЗапитЩо віддає
GET /v1/catalogУвесь каталог одним документом: categories, badges, probes, awards. Найзручніше для застосунку, який тримає каталог у себе.
GET /v1/categoriesСпеціалізації вмілостей.
GET /v1/badgesВмілості. Фільтри: ulad, category, origin, status, family, q.
GET /v1/badges/{id}Одна вмілість.
GET /v1/probesПроби з розділами й точками. Фільтр: ulad.
GET /v1/probes/{id}Одна проба.
GET /v1/awardsВідзначення й відзнаки. Фільтри: group, ulad.
GET /v1/awards/{id}Одне відзначення.
GET /v1/images/{name}Зображення. Див. нижче.

Параметри

  • krai є в усіх запитах, крім зображень і спеціалізацій. Він лишає тільки записи цього краю, наприклад ?krai=cz. Без нього приходять записи всіх країв.
  • ulad: upp, upn, upyu, usp або ups.
  • category: id спеціалізації з /v1/categories.
  • origin: край, який затвердив вмілість. Те саме, що krai, але тільки для фільтра вмілостей.
  • status: approved (затверджена) або trial (апробаційна).
  • family: усі рівні однієї вмілості, наприклад I, II і III.
  • q: пошук у назві.
  • group: група відзначень, наприклад upyu-vidznachennia.
GET /v1/badges?ulad=upyu&category=mystetska
GET /v1/badges?q=альпін
GET /v1/catalog?krai=cz
GET /v1/probes/probe-1

Кешування

Відповіді мають ETag і Cache-Control: max-age=60. Зміни в каталозі стають видно приблизно за хвилину. Якщо застосунок забирає /v1/catalog регулярно, надсилайте If-None-Match: коли нічого не змінилося, прийде порожня відповідь 304.

Невідомий id дає 404 з {"error": "not_found"}.

Записи

Ідентифікатори вмілостей, проб, точок проби й відзначень не змінюються. За ними можна зберігати, хто що здобув.

Вмілість

{
  "id": "alpinistyka",
  "title": "Альпіністика",
  "level": 3,
  "categories": ["alpinizm-ta-skelelazinnia"],
  "ulady": ["upyu"],
  "krai": "pl",
  "status": "approved",
  "images": {
    "color": "https://…/v1/images/alpinistyka_i_color.svg?v=b84363961c8d",
    "bw": null
  },
  "prerequisites": [],
  "requirements": [
    { "id": "1", "text": "Здобуде вмілості Скелелазіння ІІ і Мандрівництво." }
  ],
  "instructorRequirements": "…",
  "author": "…"
}

Поля family, level, instructorRequirements, author і updatedOn є не в усіх вмілостей. Тексти вимог написані в markdown. prerequisites містить id вмілостей, які треба мати спершу.

Проба

{
  "id": "probe-1",
  "title": "Перша проба (Скобине крило)",
  "ulad": "upyu",
  "order": 1,
  "sections": [
    {
      "id": "probe-1-section-a",
      "code": "А",
      "title": "Три головні обов’язки пластуна",
      "points": [
        { "id": "probe-1-section-a-point-1", "text": "Знає на пам’ять і пояснить Три Головні Обов’язки Пластуна." }
      ]
    }
  ],
  "points": []
}

points на верхньому рівні містить точки, що не входять у жоден розділ. order задає порядок показу.

Відзначення

{
  "id": "upyu-vidznachennia-1",
  "group": "upyu-vidznachennia",
  "title": "Перше відзначення",
  "ulad": "upyu",
  "level": 1,
  "images": { "color": "https://…", "bw": "https://…" },
  "requirements": []
}

Відзнаки КВ, ЗБ, ЛШ, ШБ та інші будуть у тому самому списку, кожна зі своєю групою в group.

Зображення

У записах зображення вже подані повними адресами. color — кольорове, bw — чорно-біле, яке можна показувати, поки вмілість не здобута. Будь-яке з них може бути null.

Параметр ?v= в адресі змінюється разом із вмістом файлу, тож браузер і CDN тримають такі зображення в кеші без обмеження строку. Адресу з ?v= краще використовувати як є і не збирати вручну.

Як додати свої вмілості

Зміни вносять редактори країв через адмінку. Вхід там за кодом, який приходить на пошту. Права видає власник каталогу.

  • Редактор краю змінює записи свого краю, додає спеціалізації й погоджує подання від свого краю.
  • Дописувач лише надсилає подання. Опублікує його редактор краю.

Одну вмілість простіше додати прямо формою в адмінці. Якщо їх багато або в них є зображення, підготуйте zip:

prague.zip
├── catalog.json
└── images/
    ├── cz-istoriia-ukraintsiv-u-chekhii-i.svg
    └── …

В адмінці натисніть «Завантажити zip». Спершу ви побачите звіт: що буде додано чи змінено, які є помилки і яких зображень бракує. Нічого не змінюється, поки ви не підтвердите.

Надсилати весь каталог не потрібно, лише те, що край додає або змінює.

Формат catalog.json

{
  "schemaVersion": 2,
  "source": { "krai": "cz", "name": "Пласт у Чехії, станиця Прага", "contact": "…" },
  "badges": [
    {
      "id": "cz-istoriia-ukraintsiv-u-chekhii-i",
      "family": "cz-istoriia-ukraintsiv-u-chekhii",
      "level": 1,
      "title": "Історія українців у Чехії I",
      "categories": ["zahalni-vmilosti"],
      "ulady": ["upyu"],
      "status": "trial",
      "images": { "color": "cz-istoriia-ukraintsiv-u-chekhii-i.svg" },
      "requirements": [
        { "id": "1", "text": "Розповість про українську еміграцію до Праги в 1920-х роках." },
        { "id": "2", "text": "Відвідає одне з місць, повʼязаних з українцями в Празі…" }
      ],
      "instructorRequirements": "Інструктор має цю вмілість або фахову освіту з історії.",
      "author": "ст.пл. Ім'я Прізвище",
      "updatedOn": "2026-10-13"
    }
  ]
}

Загальні правила

  • id пишеться латиницею, малими літерами, через дефіс. Новим записам край дає префікс свого коду, наприклад cz-. Після публікації id не змінюють.
  • Код краю — 2–3 латинські літери: ua, pl, cz, de, us, ca. Його вказують один раз у source.krai.
  • Нові вмілості краю зазвичай мають статус trial. Без статусу запис вважається затвердженим.
  • Тексти пишуться в markdown: **жирний**, *курсив*, підпункти окремими рядками з - .
  • Зображення: .svg, .png, .webp або .jpg, до 2 МБ, назва латиницею без пробілів. SVG не може містити скриптів чи посилань на зовнішні файли. Експорт з Illustrator варто пропустити через SVGOMG, це ще й зменшить файл у рази.
  • Поле з помилкою в назві, наприклад requirments, не пропускається мовчки, а дає помилку перевірки.

Поля вмілості

ПолеЩо це
id, titleОбов'язкові.
requirementsОбов'язкове. Пункти вимог: { "id": "1", "text": "…" }, де id — номер пункту.
categoriesId спеціалізацій з /v1/categories.
uladyДля яких уладів.
family, levelСпільний id і номер рівня (1–5) для вмілостей з рівнями I, II, III.
imagescolor і bw: назви файлів з теки images/.
prerequisitesId вмілостей, які треба мати спершу.
instructorRequirementsВимоги до інструктора.
author, updatedOnХто розробив і коли востаннє змінювався текст (рррр-мм-дд).
statusapproved, trial або retired.
kraiЯкщо не вказано, береться з source.krai.
notesНотатки для редакторів. У публічному API їх немає.

Проби (probes) і відзначення (awards) мають ті самі поля, що й у відповідях API, тільки зображення вказуються назвами файлів, а не адресами. Id точки проби має бути унікальним серед усіх проб.

Перевірка без надсилання

Той самий звіт можна отримати локально з репозиторію:

dotnet run --project tools/ProjectK.Catalog.Cli -- validate prague.zip --against catalog

Доповнення краю

Буває, що край хоче додати вимогу до чужої вмілості чи ще одну точку до проби. Тоді запис не копіюють, а надсилають доповнення в overrides:

"overrides": [
  {
    "krai": "cz",
    "target": "badge:aktorstvo-i",
    "addRequirements": [
      { "id": "cz-1", "text": "Візьме участь у виставі українського театру в Празі." }
    ]
  },
  {
    "krai": "cz",
    "target": "probe:probe-1",
    "addPoints": [{ "section": "А", "id": "cz-probe-1-a-1", "text": "Знає історію Пласту в Чехії." }]
  }
]

Ще можна прибрати пункти (removeRequirements, removePoints), дати запису іншу назву (title) або сховати його для краю (hidden: true). Id нових пунктів мають префікс краю.

Доповнення вже приймаються й перевіряються, але API їх поки не показує.
